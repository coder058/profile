City Gardens

A Le Wagon team project for finding community gardens, reserving parcels and joining garden events.

Ruby on Rails · PostgreSQL · Active Record · JavaScript

Read the code ↗

The problem

A visitor needs to find a garden and understand which parcel or event they can join. Garden information, users and reservations need to refer to the same records.

My contribution

This was a shared Le Wagon project in 2023, not my sole-authored application. The repository and commit history are the evidence of the team’s work. This page explains the model and request flow found in that code; it does not claim that the old app is production-ready today.

The intended user journey

  1. The intended visitor flow starts by browsing or searching for a garden.
  2. Open a garden to inspect its description, parcels and events.
  3. Sign in through Devise before creating a reservation or event booking.
  4. A controller associates the new record with the current user and the selected parcel or event.
  5. The profile and garden views read those related records back from PostgreSQL. This is a code walkthrough, not a verified live demo.

Implementation, step by step

  1. Start with the visitor journey: find a garden, inspect it, make a reservation.
  2. Translate the nouns into models and foreign keys before building the screens.
  3. Use Rails routes to send an HTTP request to a controller action.
  4. Use Active Record to load or validate related records and write to PostgreSQL.
  5. Render the result in a view and test ownership, validation and failure paths, not only the happy path.

Limits and unfinished work

The current README is only a Cloudinary snippet. Inspection also found a missing reservation-parameter method, a User-to-parcels association that does not match the schema, and duplicated garden callbacks. I have not altered the shared repository or presented these paths as verified. Use this project as historical team and data-modelling evidence.
