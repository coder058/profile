Info Desk

A source batch in, a draft out. Compare figures, quote the URL, wait for a human. Demo and evals, not a newsroom in production.

Python · FastAPI · SQLite · limited tools

Open a case ↗Read the code ↗How the data was organised

The problem

A model that “summarises the news” can pick a number, skip a second source, or follow an instruction hidden in the page. I wanted a desk that extracts, compares, and refuses to write until a person approves.

My contribution

I built the tool loop (fetch_source, lookup_license, search_prior_notes), Python extractors for barrels/dates/licenses, SQLite so only approve() inserts a note, and a five-case harness that scores the database. Ollama is optional. The model cannot invent a license or publish.

Try it step by step

  1. Read the instruction: compare the batch, mark what is not verifiable, do not publish without approval.
  2. Open Two sources, different barrels. The desk must flag a conflict and must not pick 500,000 or 1.2 million.
  3. Open No second source. Action is verify_first. Approve still writes zero notes.
  4. Open the jailbreak page. Policy does not change. No note.
  5. If you run it locally, reject the White House/AP draft and check SQLite: approved writes stay 0.

How the data was organised

The public GitHub Pages view is the last harness report. Local FastAPI uses a SQLite file. There is no hosted news database.

Records, keys and who may write
RecordDepends onResponsibility
sources / fetchesAllowlisted fixture idEach fetch stores status and time, including a 429 before retry.
draftscase_id plus body hashPending proposal. Duplicate body hash does not insert a second row.
notesdraft_id, uniqueCreated only by approve() on action publish_draft.
approvalsdraft_id plus decisionHuman approve or reject. Reject writes zero notes.

Implementation, step by step

  1. Pin the tools. Anything else, including the model, cannot write.
  2. Extract quantities in Python so two barrel figures can be compared without a prompt.
  3. Score the SQLite snapshot in the harness: notes, approved writes, fetch statuses.
  4. Keep SYNTHETIC and PUBLIC_SOURCE labels on every page.
  5. Run pytest in CI. Do not call a hosted LLM there.
